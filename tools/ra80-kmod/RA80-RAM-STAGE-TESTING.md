# RA80 RAM-only 运行期细分测试

这个包专门细分上一版 d48f4be 停在 A（两灯只有白珠亮）之后的初始化路径。
**本版灯码与上一版不同，必须用下表。** 全程固定组合，无诊断闪烁或人为停留。
每个位置只有一个码；0保留，1交接，2覆盖已经确认走过的早期启动，3..F用于运行期。

设备为3 LAN+1 WAN。1是Internet，2是System；GPIO17=2黄、19=2白、20=1黄、22=1白。
黄白两珠同时亮在这台机器看起来是粉色，所以表中称粉。

| 码 | 1：Internet | 2：System | 最后到达的位置 / 随后范围 |
|---|---|---|---|
| 0 | 灭 | 灭 | 保留，未标记 |
| 1 | 灭 | 黄 | Linux 已预检，准备交接 |
| 2 | 灭 | 白 | U-Boot reset 到运行期 cache 初始化；这一已验证的早期区间保持同一码 |
| 3 | 灭 | 粉（两珠亮） | cache 启用调用返回；随后运行期全局信息处理 |
| 4 | 黄 | 灭 | 进入主堆初始化（包括清零与内存分配器设置） |
| 5 | 黄 | 黄 | 主堆初始化返回；随后设备模型重新扫描、bootstage 初始化 |
| 6 | 黄 | 白 | 进入 board_init；即将执行 GIC 初始化 |
| 7 | 黄 | 粉（两珠亮） | GIC 调用返回；随后 SMEM flash/分区/环境位置配置、USB/时钟/UART hooks |
| 8 | 白 | 灭 | 进入板级认证信息 SCM 调用 update_board_type |
| 9 | 白 | 黄 | 板级认证调用返回；随后 stdio/串口/power 等初始化 |
| A | 白 | 白 | 进入 NAND 初始化（只做初始化，不执行擦写命令） |
| B | 白 | 粉（两珠亮） | 进入环境初始化，可能从存储读取 APPSBLENV |
| C | 粉（两珠亮） | 灭 | 环境读取和 loadaddr 初始化返回；随后其他运行期驱动/控制台/中断/按钮 |
| D | 粉（两珠亮） | 黄 | 进入 board_late_init；随后分区信息、板级变量和 ART MAC 读取 |
| E | 粉（两珠亮） | 白 | board_late_init 返回；随后剩余网络准备、webterm 和主循环入口 |
| F | 粉（两珠亮） | 粉（两珠亮） | 进入 main_loop；此细分版不再区分后续 Ethernet/HTTP 内部阶段 |

## 测试一次

只上传这个包中的 `ra80_ramboot_full.ko`；匹配的U-Boot已嵌入。不要另传bin或trigger。
断电重启回原厂Linux，核对模块MD5与包内MD5SUMS，以及原厂RAM向量：
```sh
md5sum /tmp/ra80_ramboot_full.ko
devmem 0x4a920000 32
```
向量必须为 `0xEA0000B8`，哈希匹配后执行：
```sh
sync
insmod /tmp/ra80_ramboot_full.ko execute=1
```
SSH会断开。等约30秒，记录两个灯最后的颜色（包括粉），无需数跳变次数。
若到F，可测试电脑192.168.1.2/24访问192.168.1.1的ping/网页；F本身只证明main_loop入口。
未到F时，主要证据是最终灯码，不用重复换口或ping。

保留已验证的RAM范围限制、128KiB lwIP堆、ICMP、备份/读回/内核指纹检查。
不绕过初始化，不凭猜测改变PHY/交换机配置；本包用于确定是哪一步停住。
已禁用RA80自动NAND串行训练（原流程会擦写训练区），固定使用反馈时钟。
RAM标记从NAND/env初始化之前就生效：页编程和块擦除底层拒绝执行，坏CRC不自动saveenv。
不擦写NAND/MTD/APPSBL内容；诊断模式禁止网页升级和网页命令，并跳过自动启动。
模块交接前失败会尝试恢复原厂RAM；交接后断电重启回原厂。
如果insmod报错，保留dmesg与devmem输出，不继续执行。

`CONFIG_RA80_RUNTIME_DIAGNOSTICS` 控制细分版；关闭它可恢复原完整启动灯码。
